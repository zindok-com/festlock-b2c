   아래 로직이 이미 들어 있으니 **TypeScript 모듈로 옮겨 쓴다**:
   - 사진에서 네 점으로 팔찌 구간 잡기 + 돋보기 (`photoFrom`, `solveH`, `warpStrip`)

   - 금사 디자인 (`paintGoldStrip`, `goldD`, `goldTag`)과 색 추출(`extractPalette`)
   - 3D 진열 4종: 🎀 걸기(`makeRibbonTheme('scan')`), ⭕ 손목(`makeWristTheme`), 🎠 모빌(`makeMobileTheme`), 🖼 액자(`makeFrameTheme`, 한 줄 3개/2개 벽돌 배열)
   - 카메라 맞춤·확대·이동·탭 (`updateCamera`, 포인터 처리)
3. **코드를 쓰기 전에** (a) 작업 계획 (b) 데이터 구조 초안 (c) 질문 목록만 먼저 보고한다. 대표 승인 후 단계별로 구현한다.
4. 기존 기능(타임테이블·이미지 저장·랭킹·오프라인 PWA)을 깨뜨리지 않는다. 3D 화면은 **지연 로딩**(동적 import)으로 타임테이블 페이지 용량에 영향이 없게 한다 `[추천안]`.
5. 확인하지 못한 것은 사실처럼 쓰지 말고 `[Unverified]`로 표시한다.

## 1. 목표 `[확정]`

- 사용자가 **계정 없이** 다녀온 페스티벌 팔찌를 사진으로 올려 "나만의 페스티벌 기록"을 만든다.
- 입력하는 개인 정보는 **이름**, **인스타그램 프로필 링크** 두 개뿐이다.
- 같은 종류의 티켓(같은 페스티벌·연도·등급·날짜)은 **처음 올린 사람의 팔찌 디자인을 그대로** 모두가 쓴다.
- FestLock에 들어온 사람은 다른 사람들이 어디를 다녀왔는지 **구경**할 수 있고, 버튼으로 **그 사람의 인스타그램**에 갈 수 있다.
- 한 사람당 최대 **60개** 기록 `[확정: 시안 기준]`.

## 2. 등록 흐름 (화면 순서) `[확정]`

### ① 어떤 팔찌를 올릴까요? (티켓 정보)
| 항목 | 입력 방식 |
|---|---|
| 공연/페스티벌명 | `festivals.json` 목록에서 고르기 + "목록에 없어요 → 직접 입력" |
| 연도 | 숫자 4자리 (기본값: 올해) |
| 티켓 등급 | GA / PGA / VIP / 기타(직접 입력) |
| 날짜 | Day1 / Day2 / Day3 / 3일 연속(전일권) / 기타(직접 입력) |

- 입력값으로 **티켓 종류 키**를 만든다 (3장).
- 키로 서버에 디자인이 있는지 묻는다 → ②로.

### ② 안내
- **디자인이 아직 없으면**: "당신이 처음으로 등록하는 거예요! 당신이 찍은 팔찌를 다른 사람들도 쓰게 될 거예요!" → ③ 사진 찍기로.
- **디자인이 이미 있으면** `[추천안]`: "OO님이 처음 등록한 디자인이 있어요" + 미리보기 → "이 디자인으로 내 기록에 추가" (사진 단계 생략). 아래에 작게 "내 팔찌와 달라요" → 신고/새 디자인 제안(관리자 검토)으로 연결.

### ③ 사진 찍기
- `<input type="file" accept="image/*" capture="environment">` (폰에서 바로 촬영, 앨범 선택도 가능).
- 시안과 같은 단계: 네 점으로 곧은 구간 잡기(분홍 점 = 글자 시작 쪽 윗변) → 미리보기 → **번호·QR 가리기**(끌어서 모자이크) → 방향 뒤집기 → **자동 보정 켜짐(기본)**.
- "만들 방식" 선택: **사진 그대로(기본)** / **팔찌로 디자인**(금사 등 패턴, 사진에서 색 추출).
- **AI 기능은 넣지 않는다. ✨ AI 디자인 버튼만 남긴다** `[확정]`: 누르면 "AI 디자인은 FestLock 앱에서 만나요 · 출시 소식은 인스타그램에서" 카드 + `https://www.instagram.com/festlock/` 팔로우 버튼만 뜬다. 기존 `AppSoonPopup`·`app.soon.*` 문구 키를 재사용하거나 같은 모양으로 만든다.
  - AI API 호출, AI 설계도 그리기 코드는 옮기지 않는다 (시안의 `drawRecipe`, `recipeSpec`은 쓰지 않음). 사진 자동 보정·색 추출·금사 디자인은 AI가 아니라 기기 안 계산이므로 그대로 쓴다.
- 촬영 안내 문구 `[추천안]`: "밝은 곳에서, 평평하게 펴서, 단색 바닥 위에서".

### ④ 업로드
- 올리는 것: **보정·모자이크까지 끝난 팔찌 띠 이미지(WebP)** + 디자인 정보 + 티켓 정보. **원본 사진은 올리지 않는다** `[추천안]` (용량·개인정보).
- 캔버스로 다시 인코딩하므로 사진 위치정보(EXIF)는 남지 않는다 `[Inference]` — 구현 후 실제로 확인할 것.
- 업로드 전 동의 체크(필수) `[추천안]`:
  - "이름·인스타그램 링크·팔찌 이미지가 FestLock에서 다른 사람에게 공개돼요"
  - "제가 직접 찍은 제 팔찌 사진이에요"
  - "번호·QR이 보이지 않게 가렸어요"

### ⑤ 같은 티켓은 첫 디자인 재사용
- 같은 키로 이후 들어오는 사람은 ②에서 첫 디자인을 바로 받는다.
- 첫 등록자 표시 `[추천안]`: 디자인 아래 "First by OO" (이름만, 링크는 그 사람이 공개에 동의한 경우).
- **동시에 두 사람이 처음 등록하는 경우**: 서버에서 `SET NX`(없을 때만 저장)로 먼저 저장된 것 하나만 디자인이 된다. 늦은 사람에게는 "방금 다른 분이 먼저 등록했어요"와 그 디자인을 보여 준다.

## 3. 티켓 종류 키 `[추천안]`

```
key = slug(페스티벌) + ":" + 연도 + ":" + 등급 + ":" + 날짜
예) edc-korea:2026:ga:day1   ultra-taiwan:2026:vip:full3
```
- 페스티벌이 `festivals.json`에 있으면 그 `slug`를 쓴다. 직접 입력한 이름은 소문자·공백→하이픈·특수문자 제거로 만든다.
- 직접 입력 이름은 표기가 갈려서(예: "EDC Korea" / "EDC코리아") 같은 티켓이 둘로 나뉠 수 있다 → 관리자가 키를 합치는 스크립트를 둔다 `[추천안]`.
- 등급: `ga | pga | vip | etc-<입력값>`, 날짜: `day1 | day2 | day3 | full3 | etc-<입력값>`.

## 4. 계정 없는 프로필 `[확정 + 추천안]`

- 입력: **이름**(1~20자), **인스타그램 프로필 링크**.
  - 링크 정리 `[추천안]`: `@handle`, `handle`, `instagram.com/handle`, `https://www.instagram.com/handle/?igsh=...` 모두 → `https://www.instagram.com/{handle}/` 한 형식으로. handle은 `[A-Za-z0-9._]{1,30}`만 허용.
- 계정이 없으므로 **기기 키**로 내 기록을 관리 `[추천안]`:
  - 첫 등록 때 기기에서 무작위 `ownerKey`(32자 이상)를 만들어 `localStorage`에 저장, 서버에는 해시만 저장.
  - 다른 기기·브라우저에서 관리할 수 있게 **관리 코드**(예: 단어 4개)를 한 번 보여 주고 "캡처해 두세요" 안내.
  - 관리 코드가 있어야 수정·삭제 가능.
- 남의 인스타 링크를 사칭할 수 있음 → 프로필마다 **신고** 버튼, 관리자 삭제, 인스타 DM(@festlock) 삭제 요청 안내 `[추천안]`. (README의 테이크다운 방식과 같게)

## 6. 저장소·서버 (현재 구조에 맞춤)

현재: Vercel 서버 함수(`api/*.ts`, Web `Request/Response`) + **Upstash Redis** + **Vercel Blob(Public)**.

### Upstash Redis 키 `[추천안]`
```
fl:band:design:{key}        해시  { img, style, pal(JSON), name, w, h, by(collectorId), at, status }
fl:band:collector:{id}      해시  { name, ig, ownerHash, at, count }
fl:band:items:{id}          리스트 [{ key, at }]  (최대 60)
fl:band:collectors          정렬집합  score=최근 등록 시각
fl:band:byfest:{festSlug}   정렬집합  collectorId
fl:band:reports             리스트  신고 기록
```

### Vercel Blob
- 경로: `bands/{key}.webp` (디자인당 하나, 덮어쓰지 않음).
- 이미지 크기 상한 `[추천안]`: 긴 변 1024px, WebP 품질 0.82, 파일 300KB 이하. 서버에서 형식·크기를 다시 검사한다.
- 업로드는 `@vercel/blob`의 클라이언트 업로드(서버가 토큰 발급, 경로·형식·크기 제한)로 `[Inference: 현재 dev 의존성에 @vercel/blob 2.x가 있음 — 서버 함수에서 쓰려면 dependencies로 옮겨야 할 수 있음]`.
- `src/blobHealth.ts` 주석에 Hobby 요금제 전송량 10GB 언급이 있음 → 사용자 업로드가 늘면 전송량을 넘길 수 있다 `[Unverified: 현재 요금제·한도는 확인하지 않음]`. 썸네일은 작게, 캐시 헤더는 길게.

### API `[추천안]`
| 주소 | 하는 일 |
|---|---|
| `GET /api/band-design?key=` | 디자인 있으면 반환, 없으면 404 |
| `POST /api/band-upload` | Blob 업로드 토큰 발급 (경로 `bands/{key}.webp`, image/webp, 300KB) |
| `POST /api/band-design` | 디자인 저장 (`SET NX`; 이미 있으면 기존 것 반환) |
| `POST /api/collector` | 프로필 생성/수정 (ownerKey 확인) |
| `POST /api/collection` | 내 기록에 티켓 키 추가/삭제 (60개 제한, ownerKey 확인) |
| `GET /api/collectors?cursor=&fest=` | 목록 (페이지 단위) |
| `GET /api/collector?id=` | 한 사람의 기록 |
| `POST /api/band-report` | 신고 |

- 모든 쓰기 API에 `api/fest-vote.ts`와 같은 방어: 같은 사이트 Origin → 브라우저 요청 검사 → 메모리 횟수 제한 → 값 검사 → DB 횟수 제한.
- 관리자용 스크립트 `scripts/band-admin.mjs` `[추천안]`: 신고 보기, 디자인 숨김/교체, 프로필 삭제, 키 합치기.

## 7. 화면·디자인 규칙

- 글꼴: **Pretendard 하나로 통일** `[확정: 시안 기준]`. 시안은 한글 2,350자+영문 서브셋을 내장했음 → 실제 코드에서는 기존 글꼴 로딩 방식과 맞출 것.
- 3D: `three`(시안은 r169) 의존성 추가. 진열 4종은 각각 **위에서 아래로 부드럽게 내려오는 등장 모션**을 유지 `[확정]`.
- **손목·모빌은 좌우로 끌면 360도 제한 없이 돌아간다** `[확정]`. 손을 떼면 관성으로 조금 더 돌다 멈춤 `[추천안: 시안 값 — 감속 2.2/초, 최대 8rad/초]`. 걸기·액자는 정면 위주로 좌우 일부만 돌고 놓으면 정면으로 돌아옴(시안과 같음). 모빌은 기본으로 천천히 자동 회전.
- 액자 배열: **한 줄 3개 → 한 줄 2개 번갈아**, 3개 줄 양 끝은 액자 안쪽에서 잘림 `[확정]`.
- 다국어: 기존 9개 언어(ko·en·ja·zh·zht·es·vi·th·id) 모두에 새 문구 키를 추가. 한국어 줄바꿈은 낱말 중간에서 끊지 않음(`word-break: keep-all`).
- 터치 영역 44px 이상, 모션 줄이기 설정 존중(시안의 `RM` 처리 참고).
- 공유 이미지(스토리 9:16)로 내 컬렉션 저장 `[추천안: 다음 단계]` — 기존 `exportImage.ts` 방식 재사용.

## 8. 개인정보·권리 주의 `[Unverified — 출시 전 확인 필요]`

- 이름·인스타 링크·팔찌 이미지 공개에 대한 동의, 삭제 요청 처리 방법, 개인정보 처리 안내 문구가 필요하다. 법적 요건은 확인하지 않았다.
- 팔찌에 인쇄된 페스티벌 로고·도안이 사용자 사진에 그대로 담긴다. 사용자 본인 사진을 기록용으로 보여 주는 구조지만, 공개 갤러리로 노출할 때의 권리 문제는 확인하지 않았다 → 변리사 확인 필요.
- FestLock이 페스티벌 팔찌를 **새로 그려서 복제**하는 기능은 만들지 않는다 `[확정]`. ("팔찌로 디자인"은 사진에서 색만 뽑아 FestLock 오리지널 패턴에 입히는 방식)
- 현재 `vercel.json`이 전체 `noindex`다. 컬렉터 페이지를 검색에 노출할지는 대표 결정 사항 `[결정 필요]`.

- [ ] 같은 키로 두 번째 사람이 들어오면 사진 단계 없이 첫 디자인이 붙음
- [ ] 두 사람이 동시에 처음 등록해도 디자인은 하나만 남음
- [ ] 원본 사진은 서버에 올라가지 않음 (Blob에 띠 이미지 1장만)
- [ ] 번호 가리기 영역이 업로드 이미지에 그대로 반영됨
- [ ] AI 디자인 버튼 → 출시 안내 카드 + 인스타 팔로우, AI 호출 없음
- [ ] 계정 없이 이름·인스타 링크만으로 등록, 관리 코드로 다른 기기에서 삭제 가능
- [ ] 구경하기 목록 → 컬렉터 페이지 → 인스타그램 버튼이 새 탭으로 열림
- [ ] 60개 제한, 쓰기 API 횟수 제한 동작
- [ ] 3D 화면이 지연 로딩되어 기존 페스티벌 페이지 첫 로딩 용량이 늘지 않음
- [ ] 인스타·카톡 앱 안 브라우저에서 사진 고르기·업로드 동작 확인 (`inApp.ts` 참고)
- [ ] 9개 언어 문구 누락 없음, `npm run build` 통과

## 10. 질문 목록 (구현 전 대표 확인)

1. 첫 디자인을 바로 공개할지, 관리자 확인 뒤 공개할지
2. 컬렉터 페이지 주소 형식(`/c/{id}` 등)과 검색 노출 여부
3. "내 팔찌와 달라요" 제안이 쌓였을 때 디자인 교체 기준
4. 직접 입력한 페스티벌을 목록에 자동으로 넣을지, 관리자가 넣을지
5. 관리 코드 방식(단어 4개 / 숫자 8자리 등)
