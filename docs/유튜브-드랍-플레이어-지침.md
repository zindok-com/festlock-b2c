# 유튜브 드랍 플레이어 지침 (아이폰·인앱 브라우저 재생 문제 포함)

FestLock 아티스트 창의 "드랍 미리듣기"(유튜브 공식 퍼가기 플레이어)를 만들거나 고칠 때 따르는 규칙입니다.
2026-11-02 ~ 11-03에 있었던 **아이폰·해외·인스타 브라우저에서 재생이 안 되던 문제**의 원인과 해결을 함께 기록합니다.

---

## 1. 지금 동작 (2026-11-03 배포 기준)

1. 아티스트 창이 열리면, 창 맨 위의 **접힌 칸(높이 0)** 안에 유튜브 플레이어를 미리 만들어 둔다.
2. **0.7초 뒤** 사진·이름 등 기존 내용이 부드럽게 아래로 밀려 내려가고(0.52초), 위에 생긴 공간에 플레이어가 나타나 **바로 재생**된다.
3. 재생 구간
   - 기본: Drop Studio에서 고른 구간만 재생 (5~60초)
   - `full: true`: 0초부터 영상 끝까지
4. 아래 버튼은 "▶ 드랍 N초 듣기"였다가, 재생된 뒤 "↺ 다시 듣기"로 바뀐다. 옆에 "YouTube에서 보기" 링크.
5. **인스타·카톡 등 앱 안 브라우저:** 자동 재생을 시도하지 않는다. 플레이어만 열고 그 아래 **"영상 가운데 ▶를 눌러 주세요"**를 띄운다.
6. **재생이 거절되면:** 자리를 접지 않고, 플레이어 자리에 **영상 썸네일 + 빨간 ▶ + 안내 문구 + 오류 번호**를 띄운다. 누르면 그 구간 시작점에서 YouTube가 열린다.
7. **튜토리얼로 열린 창:** 자동 재생하지 않는다. 튜토리얼 "드랍을 바로 들어 봐요" 단계에서 소리 없이 자리만 열어 보여 준다.

관련 파일: `src/components/DropPlayer.tsx`, `src/inApp.ts`, `src/drops.ts`, `index.html`, `src/styles.css`(`.drop-*`), `src/fest/strings.ts`(`f.drop.*`)

## 2. 있었던 문제와 해결

### 2-1. 아이폰에서 재생 안 됨 (오류 150/153, 1초 뒤 사라짐) — 핵심

| | 내용 |
|---|---|
| 증상 | 아이폰(사파리·크롬·인스타 모두)과 맥 사파리에서 "이 영상은 여기서 재생할 수 없어요", 플레이어가 1초 뒤 사라짐. 홍콩 사용자, 한국 사용자 모두 |
| 처음 의심한 것 | 홍콩 지역 제한, 숨겨 둔 플레이어, `origin` 설정 → **모두 원인 아님** |
| 진짜 원인 | `index.html`의 `<meta name="referrer" content="no-referrer">`. 다른 사이트에 "어디서 왔는지"를 절대 안 보내는 설정이라, 유튜브가 퍼가기 사이트를 알 수 없어 재생을 거절했다 |
| 왜 아이폰만 | 아이폰의 모든 브라우저는 사파리 엔진(WebKit)을 쓰고, 이 엔진은 페이지 설정을 그대로 따른다. 크롬 계열(안드로이드·PC 크롬·엣지)은 유튜브 플레이어가 알아서 사이트 정보를 보내서 정상이었다 |
| 해결 | `<meta name="referrer" content="strict-origin-when-cross-origin">` 로 변경. 다른 사이트에는 사이트 이름(`https://festlock.vercel.app/`)만 가고, 보던 페이지 주소는 가지 않는다 |
| 확인 | Playwright WebKit(iPhone 13 설정)으로 고치기 전 실제 사이트 = 오류 150, 고친 후 = 정상 재생. 배포 후 실제 사이트도 정상 재생 확인 |
| 놓친 이유 | 처음엔 크롬 계열(Edge)로만 테스트했다 |

> **규칙: `index.html`의 referrer 설정을 다시 `no-referrer`로 바꾸지 않는다.**

### 2-2. 인스타·카톡 앱 안 브라우저에서 자동 재생 안 됨

| | 내용 |
|---|---|
| 원인 | 앱 안 브라우저는 소리 있는 영상의 **코드로 하는 재생**을 막는다. 사이트 버튼("다시 듣기")을 눌러도 플레이어 안을 누른 게 아니라 역시 막힌다 |
| 해결 | `src/inApp.ts`로 앱 안 브라우저를 감지(인스타·카톡·페이스북·라인·네이버·다음·에브리타임·트위터). 감지되면 코드로 재생하지 않고, 플레이어를 열어 둔 채 "영상 가운데 ▶를 눌러 주세요"를 띄운다. **플레이어 안의 ▶를 직접 누르면 재생된다** |
| 참고 | 일반 아이폰 사파리도 소리 있는 자동 재생을 막을 때가 있다. 그때도 플레이어의 ▶를 누르면 된다 |

### 2-3. 안드로이드 인스타에서 드랍 칸이 아예 안 보임

| | 내용 |
|---|---|
| 원인 | 드랍 목록 파일 `/drops.json`이 브라우저에 최대 하루까지 예전 버전으로 남을 수 있었다 (`stale-while-revalidate=86400`). 예전 파일에는 그 아티스트가 없었다 |
| 해결 | `loadDrops()`가 `fetch("/drops.json", { cache: "no-cache" })` 로 매번 최신인지 확인한다 (바뀌지 않았으면 304로 가볍게) |

### 2-4. 재생이 거절되면 플레이어가 사라짐

| | 내용 |
|---|---|
| 원인 | 오류가 오면 플레이어 자리를 다시 접도록 만들어 두었다 → 사용자에겐 "떴다가 사라짐"으로 보였다 |
| 해결 | 자리를 유지하고 **썸네일(`i.ytimg.com/vi/{id}/hqdefault.jpg`) + ▶ + 안내 + 오류 번호** 카드를 띄운다. 누르면 YouTube에서 그 구간부터 열린다 |

### 2-5. 그 밖에 바뀐 것

- 플레이어에 `origin: window.location.origin`을 넘긴다 (공식 권장값, 원인과는 무관했음).
- "보일 때 플레이어 만들기"로 잠깐 바꿨다가 원인이 아님을 확인하고 **미리 로딩 방식으로 되돌렸다.**

## 3. 오류 번호 표

안내 문구 끝 괄호 안 숫자. 사용자가 캡처를 보내 주면 이 표로 원인을 찾는다.

| 번호 | 뜻 | 할 일 |
|---|---|---|
| 150 / 101 | 이 사이트에서 재생 거절 (영상 주인이 퍼가기 막음, 사이트 정보 없음, 영상 없어짐 등) | 먼저 아이폰이면 referrer 설정 확인. 영상 문제면 Studio에서 다른 영상(아티스트 본인 채널·공식 음원)으로 교체 |
| 153 | 플레이어 설정 오류 — 퍼가는 사이트 정보 없음 | `index.html` referrer 설정 확인. 주소창에 `youtube.com/embed/...`를 직접 치면 정상적으로 153이 뜨니 이건 무시 |
| 100 | 영상이 없거나 비공개 | Studio에서 영상 교체 |
| 5 | 이 브라우저의 플레이어 오류 | 대개 일시적. 새로고침 |
| 2 | 잘못된 값 (영상 id 등) | `drops.json` 값 확인 |
| -1 | 유튜브 플레이어 스크립트를 못 불러옴 | 인터넷·차단 프로그램 문제 |
| -2 | 재생 명령 실패 | 새로고침 |

> 참고: 유튜브는 요즘 없어진 영상에도 150을 돌려준다. 그래서 안내 문구는 "지역" 탓으로 단정하지 않는다.

## 4. 하지 말 것

- `index.html` referrer를 `no-referrer`로 되돌리기
- 앱 안 브라우저에서 코드로 재생하기 (`loadVideoById`·`playVideo` 자동 호출)
- 오류가 나면 플레이어 자리를 접어 버리기
- 영상·음원 내려받기, 플레이어를 200×200px보다 작게, **안 보이는 상태로 재생하기** (유튜브 규정. 미리 로딩은 재생 전이라 괜찮다)
- 튜토리얼 중 자동 재생 (처음 온 사람에게 갑자기 소리가 남)
- `drops.json`을 캐시된 예전 파일로 읽기

## 5. 테스트 방법 (드랍 플레이어를 고쳤을 때마다)

1. **크롬 계열**(Edge/Chrome)과 **WebKit(아이폰 엔진)** 둘 다에서 확인한다. 크롬만 보면 아이폰 문제를 놓친다.
   - Playwright: `webkit.launch()` + `devices["iPhone 13"]`
   - 처음 한 번 설치: `npx playwright install webkit`
2. 확인 항목
   - 유튜브 플레이어 요청에 사이트 정보가 붙는지 (요청 헤더 `referer: https://festlock.vercel.app/`)
   - 창을 열고 0.7초 뒤 자리가 열리고 영상이 재생되는지 (iframe 안 `video.paused === false`, 재생 위치가 구간 시작점)
   - 인스타 앱 정보(User-Agent에 `Instagram`)로 열면 자동 재생 없이 "▶를 눌러 주세요"가 뜨는지
   - 일부러 없는 영상 id로 바꿔(테스트 브라우저 안에서만 `drops.json` 가로채기) 썸네일 카드가 뜨는지
   - 튜토리얼 4단계에서 플레이어가 열리되 재생은 멈춰 있는지
3. 실제 폰 확인: 아이폰 사파리 / 인스타 DM 링크 / 안드로이드 크롬 / 맥 사파리
4. 해외 사용자 문제가 오면: 오류 번호 캡처 → 3장 표 → 필요하면 같은 영상을 넣는 방식만 바꾼 **비교 페이지**를 잠깐 만들어 어느 방식이 되는지 확인 (2026-11-03에 `/yt-test`로 원인을 좁혔고, 확인 후 지웠다)
