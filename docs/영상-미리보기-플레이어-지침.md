# 영상(mp4) 미리보기 플레이어 지침 (아이폰·인앱 브라우저 포함)

아티스트 창의 **미리보기 영상**(Blob에 올린 mp4)을 만들거나 고칠 때 따르는 규칙입니다.
유튜브 드랍 플레이어 지침(`유튜브-드랍-플레이어-지침.md`)의 아이폰 문제를 mp4에 맞춰 다시 따져 보고, 2026-11-11에 WebKit(아이폰 엔진)으로 직접 확인한 결과를 적었습니다.

관련 파일: `src/components/ClipPlayer.tsx`, `src/clips.ts`, `public/clips.json`, `src/fest/parts.tsx`(`PreviewPlayer`), `src/styles.css`·`src/fest/fest.css`(`.clip-*`), `src/fest/strings.ts`(`f.clip.*`), `scripts/make-clips.mjs`·`upload-clips.mjs`·`check-clips.mjs`, `scripts/test-clip-ios.mjs`

---

## 1. 지금 동작

1. 아티스트 창이 열리면 맨 위 **접힌 칸** 안에 `<video>`를 만들고 영상을 미리 받기 시작한다.
2. **0.7초 뒤** 칸이 열리고(내용이 아래로 밀림), 칸이 열리기 시작한 **0.15초 뒤** 재생을 시도한다 (자동 재생).
3. 재생 시도 순서
   1. **소리와 함께** 재생
   2. 막히면(`NotAllowedError`) **소리 없이** 재생 + 영상 왼쪽 위에 "🔇 탭하면 소리가 켜져요" 버튼
   3. 소리 없이도 막히면 영상 위 **▶ 표지**가 남는다 → 누르면 소리와 함께 재생
4. 영상이 없는 아티스트(`public/clips.json`에 없음)는 기존 **유튜브 드랍 플레이어**가 나온다 (`PreviewPlayer`가 고른다).
5. **튜토리얼로 열린 창**은 자동 재생하지 않는다 (소리 없이 자리만 열어 보여 준다).
6. 영상 주소가 둘이면(개발 서버의 내 PC 파일 → Blob) 앞 주소가 실패할 때 뒤 주소로 넘어간다. 모두 실패하면 안내 문구.

## 2. 아이폰·앱 안 브라우저에서 확인한 것

| 상황 | 브라우저 동작 | 우리 동작 | 확인 |
|---|---|---|---|
| 기본 | 자동 재생 허용 | 소리와 함께 자동 재생 | WebKit(iPhone 13)에서 창을 열고 약 0.9초 뒤 재생, 칸 높이 198px일 때 `play()` |
| 아이폰 사파리 | 소리 있는 코드 재생을 거절 | 소리 없이 자동 재생 + "소리 켜기" 버튼 → 탭하면 소리 켜짐 | 거절 조건을 흉내 내서 확인 |
| 저전력 모드 · 일부 앱 안 브라우저 | 소리 없이도 거절 | ▶ 표지가 남고, 탭하면 **누르는 순간 안에서** `play()` → 소리와 함께 재생 | 거절 조건 + 인스타 UA로 확인 |
| 파일 형식 | | H.264(Main) + AAC, `yuv420p`, `+faststart`, 긴 변 960px | WebKit `canPlayType` = probably |
| 서버 | Range 요청 필요(사파리는 없으면 재생 안 함) | Blob이 `Accept-Ranges: bytes`, `Content-Type: video/mp4`, CORS `*` | 87편 모두 Range 요청 응답 확인 |

유튜브 플레이어와 다른 점: 유튜브는 앱 안 브라우저에서 **iframe 안**을 눌러야 해서 우리 버튼으로는 재생할 수 없었지만, mp4의 ▶ 표지는 **우리 버튼**이라 앱 안 브라우저에서도 눌러서 재생된다. 그래서 앱 안 브라우저라고 자동 재생 시도를 막지 않는다 (시도하고, 막히면 표지).

## 3. 있었던 문제와 해결

### 3-1. 자동 재생이 아예 시작되지 않음 (2026-11-11, 아이폰 엔진 테스트에서 발견)

| | 내용 |
|---|---|
| 증상 | 배포용 빌드에서 창을 열어도 `play()`가 한 번도 불리지 않고 ▶ 표지만 보임. **개발 서버(`npm run dev`)에서는 정상**이라 놓쳤다 |
| 원인 | 0.7초 타이머 안에서 부른 재생 함수가 "영상 받기를 시작했는가"를 **옛날 값**(타이머를 만든 시점의 state)으로 읽었다. 이미 받는 중인데 "시작 전"으로 보고 `return` |
| 해결 | `startedRef`로 최신 값을 읽고, 영상 칸이 아직 없으면 `pending`을 켜 두었다가 `loadedMetadata`에서 재생 |
| 놓친 이유 | 개발 서버만 보았다 (React 개발 모드는 효과를 두 번 실행해 우연히 맞았다). **빌드(`vite preview`)로도, WebKit으로도 확인해야 한다** |

### 3-2. 눌렀을 때 소리가 안 남 (사파리 규칙)

사파리는 **사용자가 누르는 동작 안에서 부른 `play()`만** 소리를 허용한다. ▶ 표지를 눌렀는데 영상 칸이 아직 없으면, 칸이 만들어진 뒤(비동기)에 재생하게 되어 거절된다.
→ `play()`는 영상 칸이 없으면 `flushSync`로 **즉시 만들고 같은 함수 안에서** `v.play()`까지 부른다.

### 3-3. 개발 서버에서 ✕를 누르면 홈페이지로 이동 (2026-11-11)

| | 내용 |
|---|---|
| 증상 | 아티스트 창·튜토리얼의 ✕/건너뛰기를 누르면 창이 닫히지 않고 **홈**(`/`)으로 이동 |
| 원인 | `src/backClose.ts`(뒤로가기로 창 닫기)가 창을 열 때 history 한 칸을 넣고, 닫을 때 `history.back()`으로 뺀다. 개발 모드(StrictMode)가 "열기→닫기→다시 열기"를 한 번에 실행하면 칸 수가 어긋나, ✕에서 `back()`이 **원래 페이지 한 칸 뒤 = 홈**으로 갔다 |
| 해결 | 넣은 칸 수와 열린 창 수를 항상 같게 맞춘다. 닫을 때 바로 `back()` 하지 않고 한 틱 뒤에 맞춘다 |
| 확인 | 홈 → 카드 → 창 열기 → ✕: 같은 페이지에 머묾 / 뒤로가기: 창만 닫힘 / 튜토리얼 3단계(시연 창 열린 상태)에서 건너뛰기: 머묾 |

## 4. 하지 말 것

- 앱 안 브라우저라고 영상을 아예 재생하지 않기 (표지를 눌러서 재생할 수 있다)
- `play()`의 거절(`catch`)을 무시하기 — 거절되면 소리 없이 재시도하고, 그것도 거절되면 ▶ 표지를 남긴다
- 눌렀을 때 영상 칸을 비동기로 만들고 재생하기 (3-2)
- 영상을 H.264·AAC 말고 HEVC·ProRes 등으로 올리기, `+faststart` 없이 올리기, Range를 지원하지 않는 곳에 올리기
- 튜토리얼 중 자동 재생
- 개발 서버만 보고 "됐다"고 하기

## 5. 테스트 방법 (플레이어를 고쳤을 때마다)

1. 배포용 빌드로 확인한다: `npm run build` → `npx vite preview --port 5200`
2. **WebKit(아이폰 엔진)**으로 확인한다 (크롬만 보면 아이폰 문제를 놓친다).
   ```bash
   npm install --no-save playwright
   npx playwright install webkit
   node scripts/test-clip-ios.mjs http://localhost:5200 sound-blocked
   node scripts/test-clip-ios.mjs http://localhost:5200 all-blocked
   ```
   - `sound-blocked`: 소리 있는 코드 재생 거절 → 소리 없이 재생 + "소리 켜기" 버튼이 떠야 한다
   - `all-blocked`: 소리 없이도 거절 → ▶ 표지가 남고, 탭하면 소리와 함께 재생돼야 한다
3. 확인 항목: 창을 열고 1초 안에 재생 / ✕를 누르면 같은 페이지에 머묾 / 튜토리얼 중 재생 안 함 / 영상 없는 아티스트는 유튜브 플레이어
4. 실제 폰 확인: 아이폰 사파리 · 아이폰 저전력 모드 · 인스타 DM 링크 · 카톡 링크 · 안드로이드 크롬
   (Playwright WebKit은 사파리 엔진이지만 실제 아이폰의 저전력 모드·앱 안 설정까지는 흉내 내지 못한다)
